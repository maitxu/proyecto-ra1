01 Aplicación hipotética

Matriculator

Aplicación hipotética para detectar matrículas en imágenes de prueba de un aparcamiento.

Problema y objetivo

Una empresa de aparcamientos quiere estudiar una aplicación capaz de detectar matrículas en imágenes de prueba. La propuesta permite analizar qué lenguajes y tecnologías serían adecuados para una solución de visión artificial sin necesidad de implementar ni entrenar el modelo en este trabajo.

📷
EntradaImágenes de prueba de vehículos, preferiblemente sintéticas, anónimas o abiertas.
🧠
ProcesamientoValidación de imagen → preprocesado → detección de la matrícula → posible OCR → validación.
🔎
SalidaRegión detectada, texto de matrícula cuando proceda y nivel de confianza.
👤
Revisión humanaUn resultado de baja confianza debe quedar sujeto a comprobación antes de utilizarse.

Tabla resumen del caso

ProcesamientoValidación → redimensionado/preprocesado → detección → OCR opcional → control de confianza.

Datos necesariosImágenes sintéticas, anónimas o abiertas y, si el enfoque lo requiere, anotaciones de las matrículas.
LímiteLa aplicación propone un resultado; los casos dudosos deben pasar por revisión humana.

Lenguaje principal de la aplicación JavaScript / Node.js

Se propone para la capa web y de integración por su conexión natural con interfaz, APIs, gestión de ficheros y comunicación con el servicio de IA.

Lenguaje principal para IA Python

Se propone para el componente de IA por su ecosistema para visión artificial, tratamiento de imágenes, aprendizaje automático y disponibilidad de bibliotecas y modelos.

Descarte razonado

R se reserva principalmente para análisis estadístico y exploración; PHP destaca especialmente en backend web; Java aporta robustez empresarial; y C++ ofrece alto rendimiento, aunque con mayor complejidad de desarrollo. Para este caso de visión artificial, el ejemplo final separa Node.js para la aplicación web y Python para el componente de IA.

  recibir imagen
  SI imagen no existe ENTONCES
      mostrar "Error: falta la imagen"
      TERMINAR
  FIN SI

      mostrar "Error: formato no compatible"
      TERMINAR
  FIN SI

  imagen_preparada ← preprocesar(imagen)

  modelo_detector ← cargar_modelo("detector_matriculas")
  detecciones ← modelo_detector.predecir(imagen_preparada)

  SI detecciones está vacío ENTONCES
      devolver "No se ha detectado ninguna matrícula"
      TERMINAR
  FIN SI

  mejor ← seleccionar_deteccion(detecciones)
  recorte ← recortar(imagen_preparada, mejor.caja)

  modelo_ocr ← cargar_modelo("ocr")
  texto ← modelo_ocr.reconocer(recorte)

  confianza ← combinar_confianzas(mejor, texto)

  SI confianza < 0.70 ENTONCES
      estado ← "REVISAR"
      enviar_revision_humana(recorte, texto)
  SINO
      estado ← "PROPUESTA"
  FIN SI

  devolver_json(
      texto,
      mejor.caja,
      confianza,
      estado
  )
FIN

05 Preguntas adicionales

Conclusiones del equipo

Respuestas preparadas para trasladar al README.md.

¿IA débil o IA fuerte?

La propuesta se aproxima a una IA débil o especializada, porque el sistema está diseñado para una tarea concreta: detectar matrículas en imágenes de prueba y, opcionalmente, reconocer su texto. No pretende disponer de capacidades generales equivalentes a una inteligencia humana en múltiples dominios.

¿Modelo preentrenado o desde cero?

El planteamiento de ejemplo parte de un modelo preentrenado o una solución existente y contempla adaptación con datos del caso. Esto reduce tiempo y coste frente a entrenar un modelo completamente desde cero, especialmente en un proyecto académico sin implementación real.
